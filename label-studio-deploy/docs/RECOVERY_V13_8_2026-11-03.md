## Root causes addressed
1. The background library used to rename the canonical 'Artwork edge botanicals' layer to 'Background · <name>'. The Heritage master editor searches by the canonical name; renaming broke the link between the library, data inspector, and future derived-layout adjustments.
2. The master inspector only exposed BG-101 and BG-013, even though the main background library exposed 101 patterns. Choosing a different pattern in the library meant the inspector's select could show the wrong value.
3. Selection did not consistently distinguish the canonical master artwork layer from additional custom background layers.
4. Adding a separate background region could exceed the 100-layer cap if the document already contained another background.

## Frontend changes
- Keep the canonical master decoration layer name and element ID when changing its artwork.
- Store the selected ID as `pkg.ornament` and reset artwork review when an existing master changes background.
- The regular "Apply background" action changes the primary master decoration; "Another region" is the explicit way to add a separate layer.
- Expose all 101 built-in red/white patterns in the Advanced Decorative edge artwork select, with a fallback option for user-imported backgrounds.
- Default selected-background application to fill/crop and locked artwork, preserving master geometry.
- Keep the current background name and ID visible; highlight the selected tile.
- Add a one-click non-destructive in-browser recovery QA suite; it clones a template, tests BG-013 -> BG-101 -> serialize, verifies master identity, equal two-level header font sizes, pixel palette and 576 × 827 printer raster, and checks all 17 master IDs, background count, and duplicate IDs.
- UI QA is a simulated state/raster test, NOT a physical click or printer acceptance test.
- v13.7 prior designs and browser-stored user work remain preserved. No deliberate localStorage clearing.

## Acceptance checklist (live browser; user / Work computer-use)
1. Hard-refresh URL with `?template=master-cooked_meal&view=data&release=v13.8`.
2. Confirm top status contains v13.8, 17 label types and 101 backgrounds, current Heritage layout, and the "Run editor checks" control.
3. In Background Library choose BG-013; verify artwork changes and "Current background: BG-013". Open Advanced artwork and confirm the Decorative edge artwork select also says BG-013.
4. Choose BG-101 and confirm the master has one 'Artwork edge botanicals' layer, not a duplicated secondary background.
5. Switch to Raw Protein, apply a different background, return to Cooked Meal and verify its choice is unchanged.
6. Reload and repeat; selected background and saved package fields must persist.
7. Click Run editor checks. Inspect the total and any failed checks. Confirm it does not create a new snapshot or print.
8. Export PNG. Confirm 591 × 827 exact three-color artwork; the separate printer raster must be 576 × 827 centered crop.
9. Connect NIIMBOT B1 Pro and physically verify red/black output, alignment, quiet zones, package-ID QR scan and feed/cut. Do not mark printing accepted before this.

## Explicit design constraints
- One physical label size: 50 × 70 mm. Editor canvas: 591 × 827 pixels at 300 DPI.
- Current printer raster profile: 576 × 827 from a centered crop, not rescaled.
- Exactly white #FFFFFF, black #000000 and red #FF0000.
- Background library source artwork is 540 × 215 and applied within an editable artwork region; it is not a precomposed entire 591 × 827 label.
- Food silhouette pixels are black/white only. Red artwork is decorative and must not depict the packaged food incorrectly.
- The two-line header text has equal font size. Allergen bullets red only when present.
- The lower instruction footer remains black with white text.
- QR payload is the unique package ID alone.
- Artwork is a candidate until reviewed; validation must not silently approve dates, allergens, instructions, or print quality.

## Deferred backend contracts — do not connect in this prototype
1. `LabelTemplate`: immutable template/version IDs, type, editor JSON, artwork refs, revisions and provenance. Preserve saved customizations separately from published master defaults.
2. `BackgroundAsset`: stable BG IDs, binary color validation, source width/height, SHA checksum, theme group, approval state, primary artwork region.
3. `PackageRecord`: globally unique immutable package ID, food identity, content, weight/volume pair, preparation state, 1–4 dated events, storage, packaging, allergen declarations, reviewed instructions, optional batch/recipe/location links.
4. `LabelSnapshot`: immutable PNG bytes, SHA checksum, template version, package ID, print raster profile, creation/reprint history and explicit review attestations.
5. `PrintJob`: printer identity, stock and DPI profile, encoder output, status/events, copies, no false claims of physical print/QR success.
6. Database migration: never overwrite user templates just because master defaults change; preserve a recoverable previous-layout record. Enforce package ID uniqueness server-side; the current browser-local check is not global.
7. Export and imports: versioned JSON schema, deterministic rendering, explicit verification and diff, no silent cloud write.
